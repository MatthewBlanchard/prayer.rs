# prayer-api-contracts

`prayer-api-contracts` defines the shared Rust request and response records for
Prayer's HTTP boundary. It lets the API host and Rust consumers agree on JSON
shapes without making either depend on Axum handlers.

The crate contains DTOs for runtime and script snapshots, commander/fleet/world
state, markets and resources, facilities and storage, virtual orders,
inventory movement, crafting and logistics, social/chat data, and checkpoint
and event responses. Types use Serde's API-facing naming and, where needed by
the generated OpenAPI document, `schemars::JsonSchema`.

Some records intentionally reuse canonical domain types from `prayer-actions`,
`prayer-runtime`, `prayer-state`, and `spacemolt-lib-rs`. This crate contains
wire contracts only: routing, authorization, persistence, and live transport
belong elsewhere.

## Use

Within this workspace:

```rust
use prayer_api_contracts::{SetScriptRequest, ScriptExecutionDto};

let request = SetScriptRequest {
    script: "go station-sol;\ndock;".into(),
};
```

The external JSON contract is documented by the OpenAPI document generated by
`prayer-api`, rather than by this crate alone.

## Development

From the repository root:

```console
cargo check -p prayer-api-contracts
cargo test -p prayer-api-contracts
```
